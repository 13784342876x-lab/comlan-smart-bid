# 方案完整性及系统架构设计

## 总体设计原则

我方深刻理解天津市第五中心医院超融合平台项目对信息系统稳定运行、弹性扩展和安全可靠的迫切需求。在该项目中，超融合基础架构将作为医院核心业务系统的支撑平台，因此方案设计必须遵循一系列严谨的总体原则，以确保最终交付的系统能够满足并超越招标文件的要求。

本方案的设计原则以医疗行业数字化转型需求为导向，秉持“标准、稳定、高效、安全、易管”的核心价值，具体体现为以下几个方面。

第一，高可用与业务连续性原则。医院业务系统直接关系到患者诊疗服务的连续性，任何计划外停机都可能产生重大影响。因此，本方案从架构设计之初就将高可用作为首要目标。我们将通过超融合内置的计算与存储两层面的冗余机制，消除单点故障。无论是单个节点、单块磁盘还是单台网络设备的故障，系统均可在无需人工干预的情况下实现自动故障切换和业务恢复，确保 HIS、PACS、LIS 等核心医疗信息系统的高可用性。同时，分布式存储的多副本或纠删码策略将进一步保障数据的持久性和可访问性，即使在部分节点故障时，数据仍保持完整并可被所有剩余节点访问。

第二，开放标准化与互操作性原则。医院信息体系通常由多种品牌、多代技术的产品共同组成，超融合平台必须具备良好的开放性和标准化，才能实现与现有网络、服务器、存储及上层应用的无缝对接。我们遵循 x86 开放硬件架构、标准网络协议（如 TCP/IP、VLAN、iSCSI、NFS 等）以及主流虚拟化标准，确保平台不被特定厂商锁定。对外提供符合业界标准的北向接口（如 RESTful API、兼容 vSphere 的 API 等），便于医院现有运维监控平台或第三方管理工具进行集成，保护医院已有投资。

第三，弹性扩展与投资保护原则。随着医院业务的增长和信息系统的演进，IT 基础设施的规模需要灵活调整。本次设计的超融合架构支持“随增长付费”的扩展模式，初期可根据当前需求配置适当数量的节点，未来可按需以单节点、小集群增量进行横向扩展，扩展时新节点自动纳入资源池，实现线性、无中断的性能和容量增长。纵向扩展能力则允许现有节点通过增加内存、磁盘等方式提升能力，最大限度地保护医院的资本投入。

第四，安全与合规性原则。医院承载着大量患者隐私信息和处方等敏感数据，信息安全必须深度内建。我们将在整体设计层面融入基于角色的访问控制、操作审计、数据加密（金融/医疗行业级标准）以及网络安全分区等机制。同时，我方郑重承诺：所投产品和服务符合相关强制性规定，并在交货时根据采购人要求出具符合上述规定的证明文件（参见招标要求 TR-011）。这一承诺将贯穿于方案设计、产品选型、实施部署、验收交付的全过程，确保项目安全合规。

第五，易管理与智能运维原则。超融合平台自身应提供一体化管理界面，将计算、存储、网络资源统一纳管，实现“所见即所得”的运维体验。通过智能化监控、告警和性能分析功能，可辅助快速定位问题、识别瓶颈趋势，降低运维复杂度，使医院信息部门能够将更多精力投入业务创新。

第六，绿色节能与可持续发展原则。响应国家双碳战略和招标文件对绿色供应链管理的要求，我们在方案设计中将优先选择能效比高的硬件组件，并利用超融合的高密度集成和动态电源管理功能，优化整体功耗。同时，选用符合节能环保认证标准的产品，践行绿色供应链理念，后期可提供相关认证材料以助评分。

上述原则将贯穿于后续各子章节对总体技术路线、架构设计、功能规划及具体技术方案的论述中，并作为项目实施过程中各项决策的依据。凡涉及具体产品选型与承诺之处，均以最终确认后的技术响应为准。

## 总体技术路线

为了构建一个能够有效承载医院各类核心业务系统且具备长期演进能力的 IT 基础架构，本方案采用以超融合（HCI）为核心的软件定义数据中心（SDDC）技术路线。超融合将传统数据中心的计算、存储、网络及虚拟化功能深度整合到一套统一的 x86 服务器平台中，通过分布式存储引擎和管理软件协同工作，替代了传统的独立 SAN 存储和复杂的存储网络，从而实现架构简化、性能提升和总拥有成本（TCO）的显著降低。

在技术选型上，我方确立以下技术路线要点。

首先是计算与存储的深度融合。摒弃“计算+外置存储”的分离式架构，将服务器本地磁盘通过分布式算法组织成一个跨节点的统一存储资源池，与计算虚拟化紧密集成。这种方式消除了传统存储阵列的控制器瓶颈和 SAN 网络的复杂性，提供了更低的 IO 延迟和更高的 IOPS，特别适合对响应时间敏感的 PACS 影像读写、大型数据库事务处理等医院典型负载。

其次是采用基于开源或标准虚拟化技术的超融合平台核心。主流超融合方案普遍支持 VMware ESXi、KVM 等虚拟化平台，以及自有的精简版虚拟化层。本方案依托于一种成熟的企业级虚拟化技术栈，并经过广泛的生产环境验证。具体虚拟化内核和版本将在后续确认产品型号后明确，但整体路线坚持不绑定单一私有格式、保持开放性。

第三是分布式存储引擎。这是超融合架构的关键技术组件，它负责将每台节点上的 SSD、HDD 磁盘抽象为统一存储池，并实现数据保护、快照、复制等功能。存储引擎逻辑上与虚拟化层松耦合，使得即使虚拟化部分需升级或替换，存储数据仍可无损保留。该引擎支持多副本、纠删码等冗余策略，可根据医院不同业务对性能与容量效率的侧重进行灵活配置，比如对核心数据库使用副本提供最佳性能，对 PACS 影像归档采用纠删码节省存储空间。

第四是软件定义网络（SDN）集成。超融合系统内置虚拟交换机，将服务器内部网络和物理交换机层联动。我们将在方案中结合业务需求设计 VLAN 隔离，确保医院内不同业务系统（如内网系统、外网前置机、视频监控网等）的安全隔离。同时支持日后通过无中断升级获得更高级的微分段、防火墙等网络服务。

第五是统一管理平面。提供一个 HTML5 图形界面的管理平台，将计算、存储、网络资源统一监控和管理，极大简化运维。并且该管理平台应支持 API 调用，能与医院统一的 IT 监控系统和自动化平台对接，避免形成新的管理孤岛。

总体技术路线确保从底层硬件到上层医院业务应用形成一条高效、可靠、弹性且易于维护的技术栈，为“方案完整性及系统架构设计”提供坚实的技术理论基础。后续章节将详细描述在此路线指导下构建的具体架构方案。

## 总体方案架构

基于前述技术路线，本投标方案构建了一套逻辑清晰、功能完备的超融合基础设施总体架构。该架构从下至上可划分为物理资源层、虚拟化与分布式存储层、管理层以及业务应用层，各层职责分明、协同工作，确保为医院 HIS、PACS、电子病历等关键应用提供敏捷、可靠的支撑环境。

物理资源层由通用 x86 服务器（即超融合节点）和高速互联交换机组成。超融合节点提供计算 CPU、内存以及本地存储介质（SSD 和 HDD），所有节点通过万兆或更高速率的网络交换机互联，形成无带宽瓶颈的扁平化网络。所有设备的品牌与型号将在确定后填入，但整体物理架构支持以最小集群规模起步，后续按需扩展，避免过度投资。

虚拟化与分布式存储层是核心引擎。每台物理节点上运行虚拟化平台（Hypervisor），将 CPU、内存抽象为计算资源池，由统一管理平台进行 VM 调度。同时，节点上的本地磁盘经由超融合分布式存储引擎汇聚成一个跨所有节点的单一存储资源池。存储池向虚拟化层提供虚拟磁盘，并实现数据自动分布、动态迁移、快照、克隆、副本保护等特性。这种将计算与存储紧耦合在统一软件栈的设计，极大简化了硬件依赖，消除了独立存储控制器的性能瓶颈，并提供与本地存储相当的 IO 延迟。在该层之上，内置的虚拟交换机构建了灵活的软件定义网络，使同一集群内虚拟机间的流量可以线速转发，并通过 VLAN 与外部物理网络互通。

管理层提供基于 B/S 架构的集中管理平台，运维人员通过单一入口即可完成虚拟机生命周期管理、资源监控、性能分析、告警处理、备份策略制定等全部操作。管理平台内置的负载均衡、自动精简配置、预测性分析等智能功能，可进一步降低运维复杂度。同时，对外提供的 RESTful API 使上级运维管理系统能够集成调用，是构建统一运维架构的基石。

业务应用层则是部署于虚拟机中的各类医院信息系统，包括本次招标需承载的应用及医院未来新增的业务系统。超融合平台通过自身的快照、备份、迁移、高可用等机制为这些应用提供数据保护和业务连续性，而无需依赖应用层改造。

该总体方案架构充分体现了“软件定义”的理念，以通用硬件和横向扩展模式替代传统昂贵的专用硬件，不仅能够满足本次项目对计算和存储容量的需求，也为医院远期数字化转型打下了弹性底座。

## 部署架构

本次超融合集群计划部署于天津市第五中心医院数据中心机房内，为标准的数据中心环境。方案设计将根据招标文件要求和医院业务的具体情况，规划一个高可用、易管理的部署拓扑。

整体部署采用至少三节点的标配集群起点（具体节点数量将根据工作负载和可用性要求在实施规划阶段确认），所有超融合节点由 {{PH-FIELD-MANUFACTURER-HYPERCONVERGED}} 提供。节点将安装于同一机架或相邻机架，通过超融合互联交换机形成万兆冗余网络平面。每个超融合节点配置冗余电源、风扇和网络接口卡，上联至两台采用堆叠或 MLAG 技术的高性能交换机，以实现网络链路的冗余与负载分担。在交换侧，超融合互联交换机将按照行业最佳实践配置跨机箱链路聚合（M-LAG 或堆叠）消除单点网络故障。同时，将划分独立的 VLAN 用于存储东西向流量、管理流量、虚拟机业务流量和 vMotion 等流量，确保不同类型流量的逻辑隔离和 QoS 保障。

网络架构中，业务接入层通过核心交换机上联到医院骨干网，超融合管理网络则可通过带外管理接口或带内 VLAN 接入运维网络，方便统一监控。

存储层面，所有节点的本地磁盘通过分布式存储池以万兆互联网络进行数据副本同步。每个虚拟磁盘将根据预先设定的保护策略在多个节点上保存至少两份副本，或配置更高容错级别。该设计使得任意单台节点甚至单台交换机故障，虚拟机业务仅短暂中断后自动在其他可用节点上重启恢复，实现分钟级RTO。结合存储副本的连续性，RPO 可达零。

部署架构还考虑了日后的扩展需求。当将新的超融合节点加入现有集群时，只需上架、连线并开机，通过管理界面简单点击，系统即会自动检测新资源并纳入集群，重新平衡数据和负载，整个过程无需停机。这种平滑扩展能力使医院能够根据业务量增长逐步增加投资，符合医院的战略规划。

最终部署布局将根据现场勘察和环境条件进一步细化，形成《详细部署图》和《连线表》，并作为项目实施阶段的重要成果。

## 统一运维架构

统一运维架构是确保未来超融合平台长期稳定运行、快速定位故障并提升运维效率的关键设计。本方案将建立以超融合管理平台为核心，结合通用监控工具和标准化运维流程的一体化运维体系。

超融合管理平台本身提供全栈监控能力，涵盖基础设施层（CPU、内存、磁盘、网络接口、风扇、电源）、虚拟化层（虚拟机运行状态、资源占用）以及存储层（IOPS、吞吐量、延迟、容量使用率、数据重建进度）。平台通过预设告警阈值，能够自动发现异常并产生告警，通过短信、邮件等通道通知运维人员。同时，管理平台支持性能趋势分析和容量预测，帮助运维人员提前规划扩容时机，避免被动应急。

为实现与医院现有运维系统的整合，超融合管理平台的对外接口能力（如RESTful API等）将在产品确认后依据制造商文档进行规划，届时通过测试验证其与院方现有综合监控平台及日志分析系统的集成能力，以k），实现统一告警收敛和关联分析。同时，管理平台可提供批量操作接口，用于执行创建虚拟机、修改配置、下发快照策略等自动化任务。

此外，超融合系统支持基于角色的访问控制（RBAC），可以对不同运维角色（如初级管理员可查看，高级管理员可修改）分配精细化权限，结合登录审计日志，满足医院信息安全管理要求。安全审计日志可统一汇入医院的安全信息与事件管理（SIEM）系统。

运维流程方面，我们将参考 ITIL 最佳实践，与院方信息部门共同制定事件管理、问题管理、变更管理和发布管理流程。超融合平台的内置快照和克隆功能将作为变更前的保护手段，确保在实施重要变更时能够快速回滚。对于版本升级，超融合系统设计支持在线滚动升级，依次对每个节点进行升级而不中断业务。运维架构确保整个超融合集群处在持续可管理的状态，为业务连续性提供坚实的人员和流程支撑。

## 主要功能设计

本次提供的超融合平台集成了丰富的功能集，覆盖计算、存储、网络及数据保护等各方面，旨在为医院各类应用提供一站式服务。主要功能设计要点如下。

在计算虚拟化功能方面，支持创建和管理虚拟机，提供完整的生命周期操作：创建、删除、启动、关闭、暂停、重启、克隆、从模板部署等。虚拟机可实现在线迁移（热迁移），即在不停机的情况下将一台运行中的虚拟机从一台物理节点动态移动到另一台节点，该功能极大方便了计划内硬件维护、负载均衡和能耗优化。同时，高可用（HA）功能会在检测到某台物理节点意外故障时，自动在集群中其他健康节点上重新启动受影响的虚拟机，显著缩短业务中断时间。

存储功能设计是超融合体系的核心优势之一。平台提供分布式块存储，为每个虚拟机提供高性能的虚拟磁盘。存储功能方面，拟规划的存储特性（如精简配置、快照、数据保护等）将在产品确认后依据制造商技术文档进行验证。- 快照与快速克隆：支持对虚拟磁盘创建即时快照，用于备份、测试或开发环境的快速部署克隆操作可实现秒级的完全副本。- 数据保护：支持以多副本（如2-3副本）或纠删码策略保护数据，具体数据保护策略和容错能力将在产品确认后验证是否满足要求。纠删码可显著提高存储效率，优化备份等非主要性能敏感型数据的存储成本。- 本地化读写：为追求极致性能，存储引擎将虚拟机磁盘的数据优先写入本地 SSD 缓存并最终分布到集群，有效降低时延。

网络与安全功能设计兼顾性能与隔离。内置虚拟交换机支持 802.1Q VLAN 标记，管理员可以为每个虚拟机端口组分配合适的 VLAN，实现二层隔离。支持网络策略、安全和 QoS 策略，确保关键业务虚拟机获得足够的网络带宽。对于对安全要求极高的环境，还支持微分段功能，实现更精细的防火墙规则。

数据保护及备份功能设计，超融合平台结合快照和集成备份软件（或通过 API 与第三方备份软件对接），可实现定时备份策略、备份至外部存储目标（如 NFS 存储或本地 HDD 大容量存储）、以及数据异地容灾复制。这些功能为医院核心数据建立多层次保护，符合医疗卫生领域对数据安全和灾难恢复的监管要求。

上述功能均为超融合平台的原生能力，无须额外采购软件或硬件，共同构成一个完整而强大的基础设施功能集，服务于医院当前及未来的业务需求。

## 可靠性设计

对于一个承载医院核心业务的信息系统，任何非计划停机都可能对患者生命健康产生间接影响。因此，本方案围绕 {{PH-FIELD-OFFERED-PRODUCT-BRAND-HYPERCONVERGED}} 品牌的 {{PH-FIELD-OFFERED-PRODUCT-MODEL-HYPERCONVERGED}} 超融合系统，由 {{PH-FIELD-MANUFACTURER-HYPERCONVERGED}} 制造，设计了全方位的可靠性保障机制，覆盖硬件冗余、软件容错、数据保护和运维操作等多个层面。

硬件层可靠性是系统稳定的基础。超融合节点采用企业级服务器组件，配置热插拔冗余电源和冗余风扇模块，单电源或单风扇故障时系统可继续运行并提醒更换。内存采用 ECC 纠错内存，硬盘在 SSD 层面具备磨损均衡与坏块管理，HDD 拥有振动容错设计。网络方面，每个节点至少配置双端口万兆网卡，上行连接至两台冗余交换机，任意单条网线或单台交换机故障均不会导致节点脱离集群。所有硬件故障均有明显的指示灯告警并通过管理平台自动上报事件。

软件架构可靠性依靠超融合分布式存储和虚拟化平台的自治愈设计。{{PH-FIELD-OFFERED-PRODUCT-BRAND-HYPERCONVERGED}} 超融合系统所采用的分布式存储引擎，将数据以对象形式分布存储于集群所有节点。当某节点故障或某磁盘损坏时，系统立即启动内部数据自修复过程，在剩余健康空间上自动重建故障节点或磁盘上的数据副本，无需管理员干预，数据冗余度实时恢复至设定水平。同时，虚拟化层的高可用（HA）代理会持续监测所有节点的心跳，当判定某一节点完全故障时，会自动在正常节点上重新注册并启动其上运行的虚拟机。整个过程对终端用户基本透明。

数据保护可靠性方面，可为不同重要等级的业务自定义保护策略。例如，对于核心数据库，采用同步三副本策略，保证每次写操作被确认写入至少两个不同节点的存储介质后才返回应用，杜绝静默数据丢失。对于影像归档等写后读为主的业务，则可使用效率更高的纠删码策略，既保证可靠性又提高空间利用率。此外，内置的硬件快照调度可创建密集恢复点，用于逻辑错误（如误删除）情况下的快速恢复。

网络可靠性设计中，存储网络与管理网络分离，存储东西向流量基于专用 VLAN 或物理隔离的网络平面，避免管理风暴影响 IO 性能。交换机层级通过堆叠/MLAG 加链路聚合，形成无环路的二层拓扑，确保网络路径的负载均衡和快速故障切换。

运维操作可靠性体现在计划内维护对业务的无影响。{{PH-FIELD-OFFERED-PRODUCT-BRAND-HYPERCONVERGED}} 系统支持在线软件升级，可依次对每个节点实行“疏散—升级—回滚”操作，升级期间虚拟机保持在其它节点运行；在线替换故障零部件（如硬盘、电源）时，数据保护机制确保替换期间数据不丢失。

通过上述多维度的可靠性设计，本超融合平台将确保医院业务系统达到业务连续性需求的最高标准。详细的可靠性指标（如 RPO、RTO、可用性百分比等）将依据最终确认的产品型号和配置进行计算并在《详细技术方案》中明确。

存储子系统是决定超融合 IO 性能的重点。节点内部磁盘配置采用“SSD + HDD”的分层混合架构或全闪存架构。通常，会配置两块高性能 NVMe SSD 作为读写缓存以及超融合系统管理安装盘数块 SATA/SAS SSD 用作容量层或作为全闪存架构的热数据层大容量 HDD 则用于存放温数据和冷数据。配置策略将根据医院应用的数据访问模式定制，例如将数据库和 PACS 近期影像放在 SSD 层，历史归档数据放在 HDD 层。同时，支持热插拔功能，便于在线更换损坏磁盘，运维人员无需停机即可维护。硬盘品牌、容量和具体数量待产品型号确定后明确。

网络方面，每节点至少配备 2 个 10GbE/25GbE SFP+/SFP28 端口，用于存储和 VM 业务网络，并可能再提供 1 个 1GbE RJ45 端口用于带外管理。通过链路聚合或绑定模式，实现双万兆上联至互联交换机，确保高吞吐和高可用。部分高端机型可能支持 100GbE 网络，为未来快速扩展预留空间。

物理特性和硬件冗余方面，超融合节点采用 1U 或 2U 机架式机箱，配备冗余热插拔电源（1+1 冗余）、冗余热插拔风扇模块，以及可选的 TPM 安全芯片。节点设计符合数据中心标准，支持-48V 直流电源选项，适应医院可能的不同供电环境。

在软件集成上，节点出厂预装超融合厂商的虚拟化存储软件，或支持无状态启动，可通过管理中心自动化部署，实现“开箱即用”，缩短实施周期。最终节点硬件配置将根据投标阶段确定的型号以及《采购清单》中的技术要求进行一对一点对点应答，确保完全满足招标文件供货要求。
